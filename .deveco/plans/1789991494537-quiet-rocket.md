# 订单信息自动导入 — 实施计划

## Goal

用户在电商 App 复制商品分享链接或截图订单页后，打开咖啡志即可自动将商品信息（名称/品种、价格、商家、日期）预填到咖啡豆/器具表单，确认后保存，替代手工录入。

**已确认的交互决策**（用户已批准）：
- 不做悬浮球——全局悬浮窗需要 `SYSTEM_FLOAT_WINDOW`（system_core 级，第三方应用即使 ACL 也无法申请，SDK 已验证），应用内悬浮球用户也不要。
- 导入路径一：**剪贴板链接导入**（分享文本解析为主 + best-effort 网页 `<title>` 抓取为辅）。
- 导入路径二：**截图 OCR 导入**（Core Vision Kit `textRecognition`，SDK 已验证 API 10+ 可用）。
- 两类订单（咖啡豆/器具）都支持，识别结果先预填、用户确认后保存。

## Scope / Non-goals

**包含**：剪贴板自动检测（可关闭）、手动「从剪贴板导入」入口、系统截图→相册选图→OCR→预填、导入预览弹层、防重复提示。

**不包含**：全局/应用内悬浮球、系统分享面板接收（sendData skill，购物 App 命中率低）、订单页精确版式适配、冲煮记录导入。

## Current State And Constraints

- 现有代码：三 Tab 框架（Index.ets）、三个表单页（BeanFormPage/EquipmentFormPage/BrewFormPage）、OptionSheet 可复用底部弹层、SettingsStore（Preferences）、AppStorage 版本号刷新机制均已就绪。
- **已验证的 API 形态**（SDK 6.1.1(24) 实测 d.ts）：
  - OCR：`import { textRecognition } from '@kit.CoreVisionKit'` → `await textRecognition.init(): Promise<boolean>`（API 12+）→ `await textRecognition.recognizeText({ pixelMap: pm }: textRecognition.VisionInfo): Promise<textRecognition.TextRecognitionResult>`，结果 `result.value`（全文）+ `result.blocks[].lines[].value`（按行）。
  - 剪贴板：`import { pasteboard } from '@kit.BasicServicesKit'` → `const data: pasteboard.PasteData = await pasteboard.getSystemPasteboard().getData()` → `data.getPrimaryText(): string`。
  - HTTP：`import { http } from '@kit.NetworkKit'` → `const req = http.createHttp(); const resp = await req.request(url, { method: http.RequestMethod.GET, connectTimeout: 5000, readTimeout: 5000, header: {...} }); resp.result as string; req.destroy();`。需在 module.json5 声明 `ohos.permission.INTERNET`（normal 级 system_grant，无弹窗）。
  - 相册选图：`import { picker, fileIo as fs } from '@kit.CoreFileKit'` → `picker.PhotoViewPicker` + `PhotoSelectOptions`（`MIMEType = picker.PhotoViewMIMETypes.IMAGE_TYPE`、`maxSelectNumber = 1`）→ `select(): Promise<picker.PhotoSelectResult>` → `result.photoUris[0]` → `fs.openSync(uri, fs.OpenMode.READ_ONLY)` → `image.createImageSource(file.fd)` → `createPixelMap()`。无需权限。
- **ArkTS 硬约束**（延续既有代码规范）：禁正则字面量 → 一律 `new RegExp('...')`；禁解构；对象字面量必须有类型上下文；async 方法显式 `Promise<T>`；`catch (e)` 无类型注解，用 `(e as BusinessError).code` 记日志；不用 `$$` 双向绑定；UIContext 系 API（`this.getUIContext().getRouter()/getPromptAction()/animateTo()`）。
- **系统限制说明**（实现时不得尝试绕过）：
  - 剪贴板读取：HarmonyOS NEXT 对前台应用读剪贴板可能有系统级隐私提示/确认，读取失败（拒绝/空）必须静默降级，不得报错打断用户。
  - 淘宝短链抓取大概率撞登录墙——`LinkFetcher` 必须 5 秒超时 + 失败静默返回空串，绝不能阻塞预览弹层。
  - OCR 为设备端能力，`init()` 可能失败（错误码 1001400001/1001400002）——catch 后 toast 提示并中止。

## Design

### 1. 数据流总览

```
路径一（链接导入）:
  用户在淘宝/京东复制分享文本 → 切回咖啡志 → Index.onPageShow → ClipboardImport.check()
  → 读剪贴板 → ShareParser.parseShareText() 解析 → LinkFetcher.fetchTitle() 补充(best-effort)
  → ImportPreviewSheet 预览（平台/标题/价格/分类建议）→ 用户选「填入咖啡豆表单」或「填入器具表单」
  → AppStorage.setOrCreate('importDraft', draft) → pushUrl 表单页 → 表单 aboutToAppear 消费预填 → 确认保存

路径二（截图 OCR 导入）:
  表单页点「📷 从截图导入」→ OcrImport.pickAndRecognize()（选图→OCR）
  → OcrParser.parseOrderText() 提取字段 → 直接预填当前表单 → toast「已识别填入 N 项，请核对」→ 确认保存
```

### 2. model/ImportDraft.ets（新建）

```ets
export class ImportDraft {
  target: string = '';      // 'bean' | 'equipment'，空 = 未消费
  title: string = '';       // 商品标题（咖啡豆→名称；器具→作为型号/种类参考）
  price: number = -1;       // -1 = 未识别
  vendor: string = '';      // 商家/平台名
  purchaseDate: number = Date.now();
  sourceUrl: string = '';   // 来源链接（存表单备注？不，仅预览展示）
}
```
- AppStorage key 常量追加到 `common/Theme.ets` 的 `AppKeys`：`IMPORT_DRAFT = 'importDraft'`、`AUTO_CLIPBOARD = 'autoClipboard'`、`LAST_IMPORTED = 'lastImportedText'`。
- 表单页消费后 `AppStorage.setOrCreate('importDraft', new ImportDraft())`（置空）。

### 3. service/ShareParser.ets（新建）— 纯解析，无副作用

`parseShareText(text: string): ShareParseResult`，规则（全部 `new RegExp`）：
- **平台**：含 `【淘宝】` 或 `taobao|tb.cn` → `'淘宝'`；`【京东】|jd.com` → `'京东'`；`【拼多多】|pinduoduo|yangkeduo` → `'拼多多'`；否则 `''`。
- **URL**：`new RegExp('https?://[^\\s，,。"】]+')` 取第一个匹配。
- **价格**：`new RegExp('[¥￥]\\s*([0-9]+(?:\\.[0-9]{1,2})?)')` 取第一个，`Number()` 转换；无则 -1。
- **标题**：原始文本去掉【xx】前缀段、URL、价格片段、常见口号（`复制这段话|打开淘宝|点击链接|￥[^￥]*￥`淘口令）后，按空白/标点切段取最长段（>3 字符）。
- **分类 category**：`'bean' | 'equipment' | 'unknown'`：
  - 咖啡豆关键词：`咖啡豆|耶加|瑰夏|蓝山|曼特宁|哥伦比亚|埃塞|危地马拉|云南|水洗|日晒|蜜处理|意式豆|单品豆|g装`
  - 器具关键词：`壶|磨豆机|滤杯|咖啡机|手冲|法压|摩卡|爱乐压|电子秤|温度计|滤纸|粉锤|拉花缸`
  - 两类都命中或都不命中 → `'unknown'`（预览层让用户手选）。
- **ShareParseResult 类**字段：`platform: string`、`title: string`、`price: number`、`url: string`、`category: string`，全部默认值初始化（ArkTS 类规范）。

### 4. service/LinkFetcher.ets（新建）

`fetchTitle(url: string): Promise<string>`：
- 仅当 url 以 `http` 开头才请求；`http.createHttp()` + GET，`connectTimeout/readTimeout: 5000`，`header` 设置浏览器 UA（`Mozilla/5.0 (Linux; Android 14) ...`）与 `Accept: text/html`。
- `resp.result as string` 后用 `new RegExp('<title[^>]*>([^<]+)</title>')` 提取（HTML entity 做 `&amp;`→`&` 简单替换）。
- **脏数据过滤**：title 命中 `登录|验证|滑动|访问受限|安全验证|403|404` → 返回 `''`。
- 全程 try/catch，任何失败返回 `''`；finally 中 `req.destroy()`。
- 不跟随跳转配置保持默认；京东 m 页通常可取到含商品名的 title，淘宝失败可接受。

### 5. service/OcrParser.ets（新建）

`parseOrderText(fullText: string): OcrParseResult`——输入 `result.value` 全文（含换行），逐行 `split('\n')` 处理：
- **价格**：同上 ¥/￥ 正则，全文本第一个匹配。
- **日期**：`new RegExp('([0-9]{4})[-/年.]([0-9]{1,2})[-/月.]([0-9]{1,2})')` 取第一个匹配，转 `new Date(y, m-1, d, 12).getTime()`；无则 `Date.now()`。
- **商家**：优先匹配含 `旗舰店|专营店|专卖店|京东自营|自营` 的行，从中提取 `[\u4e00-\u9fa5A-Za-z0-9]{2,20}(?:旗舰店|专营店|专卖店)` 片段；无则回退整行（去价格/日期片段）。
- **标题（咖啡豆）**：含咖啡豆关键词（复用 ShareParser 同一套常量，提取到 `model/Models.ets` 或 ImportDraft.ets 中共享 `CategoryKeywords` 类）的最长行，行内剥除价格与日期片段。
- **标题（器具）**：含器具关键词的最长行；**品牌**：命中预设品牌表 `Hario|Timemore|泰摩|Fellow|比乐蒂|Bialetti|德龙|Delonghi|Barsetto|百胜图|马克西姆|东菱|苏泊尔|Hero|brewista|Hario`（忽略大小写）即提取；**型号**：标题中 `[A-Za-z]+[-]?[0-9][A-Za-z0-9-]*` 样式片段（如 `V60`、`1Zpresso`）。
- **OcrParseResult 类**字段与两类表单字段对应：`name、variety、price、vendor、purchaseDate、type、brand、model`，未识别字段用空串/-1 默认值。

### 6. service/OcrImport.ets（新建）

`pickAndRecognize(context: common.UIAbilityContext): Promise<OcrParseResult | undefined>` 编排：
1. PhotoViewPicker 选图（单选），取消 → 返回 undefined。
2. `fs.openSync(uri, fs.OpenMode.READ_ONLY)` → `image.createImageSource(file.fd)` → `await source.createPixelMap()` → finally 中 `source.release()` + `fs.closeSync(file)` + `pm.release()`。
3. `try { await textRecognition.init() } catch (e) { 记日志并继续 }` → `const r: textRecognition.TextRecognitionResult = await textRecognition.recognizeText({ pixelMap: pm })`。
4. 成功 → `OcrParser.parseOrderText(r.value)` 返回；OCR 异常 → catch → toast「识别失败，请重试」→ 返回 undefined。
- 像素过大时 `pm.scale()` 缩到最长边 ≤ 1280 提高识别速度（`pm.getImageInfo().size.width/height` 判断）。

### 7. service/ClipboardImport.ets（新建）

`checkAndImport(context: common.UIAbilityContext): Promise<void>`（由 Index.onPageShow 调用）：
1. 读设置：`autoClipboard` 关闭（SettingsStore 新增 get/set，Preferences 持久化）→ 直接返回。
2. `await pasteboard.getSystemPasteboard().getData()` try/catch → `getPrimaryText()`；空串/长度 > 500 → 返回。
3. **防重复**：文本与 `AppStorage.get<string>('lastImportedText')` 相同 → 返回；且必须有 URL 且 URL 域名命中电商白名单正则（`taobao|tb.cn|tmall|jd.com|pinduoduo|yangkeduo|pdd`）才继续——避免每次切前台对无关剪贴板内容弹窗。
4. `ShareParser.parseShareText()` → 若 title 为空，`await LinkFetcher.fetchTitle(url)` 补充（仍空 → 用「来自{platform}的商品」占位）。
5. `AppStorage.setOrCreate('lastImportedText', text)`（无论用户后续选择与否，同一文本本次会话不再弹）。
6. 组装 ImportDraft，展示 ImportPreviewSheet（见下）。

### 8. components/ImportPreviewSheet.ets（新建，风格复用 OptionSheet 模式）

- 条件渲染于 Index 顶层 Stack：`@State showImportSheet: boolean` + `importDraft: ImportDraft` + `parseResult`。
- 结构：半透明遮罩（点击取消）+ 底部圆角磨砂面板（`backgroundBlurStyle(BlurStyle.Thick)` + `translate` transition + `animateTo`，与 OptionSheet 相同动效）。
- 内容：
  - 标题「识别到商品链接」
  - 字段预览行：平台、商品名（最多 2 行 ellipsis）、价格、来源链接（小字灰）
  - 两个主按钮：「填入咖啡豆表单」/「填入器具表单」——按 `parseResult.category` 预高亮推荐项（unknown 则两个同权重）
  - 次要按钮：「取消」
- 点击按钮 → `AppStorage.setOrCreate('importDraft', draft)`（draft.target 置对应值）→ `getRouter().pushUrl({ url: 'pages/BeanFormPage' | 'pages/EquipmentFormPage', params: { id: -1 } })` → 关闭弹层。

### 9. 修改 pages/Index.ets

- 增加 `onPageShow(): void` → `ClipboardImport.checkAndImport(getContext(this) as common.UIAbilityContext)`（async 内部消化，不阻塞）。
- 加号菜单 addOptions 增加第 4 项：`{ icon: '🔗', label: '从剪贴板导入', action: 同 checkAndImport }`。
- 顶层 Stack 增加 `if (this.showImportSheet) { ImportPreviewSheet({...}) }`（与 AddRecordSheet 同层级）。
- **注意**：从表单页返回 Index 会再次触发 onPageShow——若剪贴板内容仍是刚处理过的链接，防重复机制（lastImportedText）会拦住，不会二次弹窗。

### 10. 修改两个表单页

**BeanFormPage / EquipmentFormPage 共同改动**：
1. `aboutToAppear` 末尾：`const d: ImportDraft = AppStorage.get<ImportDraft>('importDraft') ?? new ImportDraft()` → 若 `d.target` 匹配本页（bean/equipment）则逐字段预填：
   - BeanFormPage：`name = d.title`（含咖啡豆关键词时 `variety = d.title`、`name = ''` 反之）、`price = d.price > 0 ? '${d.price}' : ''`、`vendor = d.vendor`、`purchaseDate = d.purchaseDate`；toast「已从链接导入，请核对」。
   - EquipmentFormPage：标题含品牌表命中 → `brand`，型号正则命中 → `model`，剩余 → `type` 参考（若命中 EquipmentType.ALL 关键词则直接设置，否则留空）；`price/vendor/purchaseDate` 同上。
   - 消费后立即 `AppStorage.setOrCreate('importDraft', new ImportDraft())` 置空。
2. header 下方增加「📷 从截图导入」描边按钮（全宽、白底圆角、主题色描边）：
   - onClick → `OcrImport.pickAndRecognize()` → 返回 OcrParseResult 后逐字段填充当前表单（BeanFormPage：variety/name/vendor/price/purchaseDate；EquipmentFormPage：type/brand/model/price/purchaseDate/vendor），`this.errorText` 清空，toast「已识别填入 N 项，请核对」（N = 非空字段数）。
   - 识别期间按钮置 `@State importing: boolean = true` 防重复点击，文案变「识别中…」。

### 11. 修改 MineView + SettingsStore

- SettingsStore 新增：`isAutoClipboard(): boolean` / `setAutoClipboard(on: boolean)`（Preferences key `autoClipboard`，默认 true）。
- MineView「设置」组新增一行「自动检测剪贴板链接」，右侧 `Toggle({ type: ToggleType.Switch, isOn: this.autoClipboard })` + `.onChange((value: boolean) => {...})`，并在行下方加小字说明「在购物 App 复制商品链接后打开咖啡志，即可自动识别填入」。

## Execution Sequence

1. module.json5 权限 → Theme.ets key 常量 → ImportDraft.ets（模型先行）。
2. ShareParser → OcrParser（纯函数，先写先验）→ LinkFetcher。
3. OcrImport → ClipboardImport（编排层）。
4. ImportPreviewSheet → Index.ets 集成 → 表单页集成 → MineView 开关。
5. 每写完一个 .ets 立即 `arkts_check`（重点：正则一律 `new RegExp`、对象字面量类型上下文、Promise 显式返回类型、pasteboard/http/ocr 的 catch 处理）。
6. 全量 arkts_check → build_project → 模拟器验证。

| 防重复 | 不改剪贴板再次切前台 | 不再弹窗；换一段文本后才再次弹出 |

| 截图 OCR | 表单页「从截图导入」→ 选一张含文字的图片 | 识别后字段预填 + toast；取消选图无副作用 |
| OCR 失败路径 | 选一张纯色图片 | toast「识别失败/未识别到内容」，表单不被污染 |
| 开关 | MineView 关闭自动检测后复制链接切前台 | 不弹窗；手动入口仍可用 |
| 剪贴板读取被拒 | 剪贴板为空/读取异常 | 静默无反应，无报错弹窗 |
| 回归 | 原三 Tab 增删改查、主题色、清空数据 | 全部正常 |

## Risks And Compatibility

- **剪贴板隐私管控**：HarmonyOS NEXT 前台读取剪贴板可能触发系统确认提示，体验因系统版本而异——设计上已做静默降级 + 设置开关，最坏情况退化为仅手动入口可用。
- **淘宝链接抓取大概率失败**：预期内，LinkFetcher 失败静默，主路径是分享文本自身解析（分享文本通常自带商品标题）。
- **OCR 识别质量**：订单截图版式各异，字段提取是启发式——所有结果都预填可改，不会存入错误数据；`textRecognition` 错误码（1001400001/1001400002）已设计 catch。
- **正则兼容**：ArkTS 禁字面量正则，全部 `new RegExp`，注意转义（`\\s` 等）。
- **PhotoPicker URI 权限**：picker 授权临时 URI，`fs.openSync` 只读打开即可，无需持久化授权。
- **兼容性**：全部 API（pasteboard/http/picker/image/textRecognition）在 API 12 均可用，目标 SDK 6.1.1(24) 无风险；新增权限仅 INTERNET（normal），对现有签名配置无影响。
